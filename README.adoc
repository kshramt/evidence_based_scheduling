= Evidence Based Scheduling

image:https://github.com/kshramt/evidence_based_scheduling/actions/workflows/ci.yml/badge.svg["ci", link="https://github.com/kshramt/evidence_based_scheduling/actions/workflows/ci.yml"]

This is a TODO application, which offers the following features:

1. https://www.joelonsoftware.com/2007/10/26/evidence-based-scheduling/[The evidence based scheduling method]
2. https://jameshfisher.com/2013/12/19/todo-dag/[DAG-based dependency management]
3. https://web.dev/learn/pwa/[Offline-first PWA]

== Usage

=== Deploy on the Linux amd64 server

Keep the existing checkout on the server so Compose continues to use the same project and PostgreSQL data directory. Check that `docker --context rootless info` connects to the daemon you currently use. If the context does not exist, create it once.

[source,bash]
----
docker context create rootless --docker "host=unix:///run/user/$(id -u)/docker.sock"
----

Create `~/.config/evidence-based-scheduling/deploy.env` on the server with mode `0600`. Use the current database passwords. If you already set `MY_HOST_PGDATA` or custom ports, carry those settings over.

[source,bash]
----
install -d -m 700 ~/.config/evidence-based-scheduling
(umask 077 && touch ~/.config/evidence-based-scheduling/deploy.env)
chmod 600 ~/.config/evidence-based-scheduling/deploy.env
${EDITOR:-vi} ~/.config/evidence-based-scheduling/deploy.env
----

[source,dotenv]
----
_POSTGRES_PASSWORD='existing-postgres-password'
_POSTGRES_APP_USER_PASSWORD='existing-app-password'
----

To check that Compose can read the settings without printing the resolved configuration, run this from the checkout.

[source,bash]
----
docker compose --env-file ~/.config/evidence-based-scheduling/deploy.env -f compose.yaml -f compose.prod.yaml config -q
----

After the main CI run has published the images, SSH in, enter the existing checkout on `main`, and run the following command.

[source,bash]
----
git pull --ff-only origin main && scripts/deploy.sh
curl -fsS http://127.0.0.1:8080/api/v2/sys/health
----

Use the configured Envoy HTTP port in the health check. The deploy script uses the checked-out commit's `h-<sha>-linux-amd64` tag for all images. Compose pulls the images before recreating any containers. If a pull fails, retry once the images are available.

=== Upgrade an existing PostgreSQL 16 deployment to 17

After checking out the PostgreSQL 17 deployment commit, run the migration from
Bash in the existing checkout. Its published images must be available.

[source,bash]
----
scripts/migrate_postgres_17.sh
----

The defaults are Docker context `rootless`, environment file
`~/.config/evidence-based-scheduling/deploy.env`, and a new data directory
`~/d/ebs-postgres-17`. The script uses the checked-out commit's image tag.
Override these with `DOCKER_CONTEXT` (or `DOCKER_HOST`), `COMPOSE_ENV_FILES`,
`NEW_PGDATA`, and `TAG` when needed. Python 3 is required on the server.
The destination directory must not exist.

The script pulls all destination images, records the current image references
and data mount, stops application writers, and creates private role and database
backups. PostgreSQL remains running during the logical backup. It then starts
PostgreSQL 17 on the new directory and restores the roles and database. Before
restarting the application it checks the server version, user and patch counts,
and the restored app role's TCP authentication. It updates `MY_HOST_PGDATA` in
`deploy.env` atomically and starts the application with `scripts/deploy.sh`.

After completion, check `/api/v2/sys/health`, open an existing task, and verify
that a small edit survives reloading. Keep the printed backup directory and the
old data directory. The backup includes the previous environment file and a
`rollback.sh` that restores the old configuration and exact running images.
If migration fails, inspect the reported error before running the rollback
script. Once clients have written to PostgreSQL 17, reconcile those writes
before switching back to the old cluster.

=== Back up the running PostgreSQL database

Run the backup on the deployment host with an existing destination directory.

[source,bash]
----
scripts/backup_postgres.sh /path/to/backup-directory
----

The command uses the deployment's Docker context and environment file. Set
`DOCKER_CONTEXT` or `DOCKER_HOST`, and `COMPOSE_ENV_FILES` to select a different
deployment. The database remains online while the command dumps its roles and
data. It reads the archive with `pg_restore` in SQL output mode and discards
the generated SQL. After validation, it prints the path to a private directory
containing `roles.sql`, `postgres.dump`, and their SHA-256 checksums in
`SHA256SUMS`. The backup contains role password verifiers and application data.
Choose where to keep copies and how long to retain them for your deployment.

Keep `SHA256SUMS` with the backup files. After copying the backup or before a
restoration, run `sha256sum -c SHA256SUMS` from inside the backup directory
(`shasum -a 256 -c SHA256SUMS` on systems without `sha256sum`).

Use a fresh PostgreSQL cluster for a restoration rehearsal. CI restores the
roles and database into an isolated cluster, then checks the restored data and
app password over TCP. Run the same rehearsal locally with synthetic data
using the PostgreSQL image named in the Dockerfile.

[source,bash]
----
image="$(awk '$1 == "FROM" && $4 == "base_postgres" { print $2 }' Dockerfile)"
tests/test_postgres_restore.sh "$image" "$image"
----

=== Start with an explicit image tag

[source,bash]
----
TAG=latest-linux-amd64 _POSTGRES_PASSWORD=postgres_password _POSTGRES_APP_USER_PASSWORD=postgres_app_user_password scripts/launch.sh
----

== Development

=== Local tools

Install https://mise.jdx.dev/installing-mise.html[mise] (on macOS with Homebrew, `brew install mise`). Run these commands from the repository root.

[source,bash]
----
mise install
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm --dir client exec playwright install chromium
----

Run the client checks, which launch Chromium.

[source,bash]
----
mise exec -- make check
----

After updating Playwright, rerun the Chromium installation command before running the client checks.

Run the same deployment, backup, migration, and toolchain tests as CI with
Python 3.11 or newer, ShellCheck, and shfmt on your path. These checks work
without a running Docker daemon.

[source,bash]
----
make check_scripts
----

When updating a tool version, update `mise.toml` and the corresponding Dockerfile pin together.

=== Run the app locally

Start the app and its services with Docker Compose.

[source,bash]
----
MY_HOST_PGDATA=./pgdata1 _POSTGRES_PASSWORD=postgres_password _POSTGRES_APP_USER_PASSWORD=postgres_app_user_password docker compose -f compose.yaml -f compose.dev.yaml up --build
----

Open `http://localhost:8080/app/`. To work on the client with Vite, keep Compose running and start Vite in a second terminal.

[source,bash]
----
mise exec -- pnpm --dir client dev --port 3122
----

Open `http://localhost:3122`.

=== DevContainer

Please share `/` to run the devcontainer on macOS ( https://docs.docker.com/desktop/settings/mac/#file-sharing ).

Please run the following commands for the first run.

[source,bash]
----
$ sudo chown <you>:<you> ~/.cache
$ sudo chown <you>:<you> ~/.cargo
----
