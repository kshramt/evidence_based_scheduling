## 2024-04-06 - Missing API Security Headers
**Vulnerability:** The `api_v2` Axum application was missing essential security headers (Content-Security-Policy, Strict-Transport-Security, X-Frame-Options, X-Content-Type-Options, Referrer-Policy). Axum v0.7 does not set these by default, exposing the API to various injection and misconfiguration vulnerabilities (like clickjacking or MIME-sniffing).
**Learning:** In a Rust Axum application, middleware like `tower_http::set_header::SetResponseHeaderLayer` must be explicitly added to enforce HTTP security headers. Moreover, to unit test the header enforcement without spinning up the Axum server or triggering offline DB connections, we must target a non-existent route (`/api/v2/not-found`) and send a oneshot request. This successfully invokes the middleware layers and responds with a 404 while applying the appropriate security headers.
**Prevention:** Future Axum/Tower applications or new API endpoints must always inherit the root router configuration that contains `SetResponseHeaderLayer`.
