## 2024-06-01 - Missing Strict Security Headers in Rust Axum API
**Vulnerability:** The Rust backend (`api_v2`) lacked standard strict security HTTP headers such as `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, and `Referrer-Policy`. This exposed the application to various attacks like clickjacking, MIME-type sniffing, and cross-site scripting (XSS) via injected frames, and lacked forced TLS.
**Learning:** Axum requires chaining multiple `.layer(tower_http::set_header::SetResponseHeaderLayer::overriding(...))` directly on the router for each header, rather than a single layer builder, due to tower-http 0.6 changes. Further, `hyper::header` keys and static `HeaderValue`s must be explicitly matched. Specifically, non-standard typed headers like `referrer-policy` must be instantiated via `hyper::header::HeaderName::from_static()`.
**Prevention:** Always ensure standard security headers are applied to the top-level app router before initializing the server, ideally relying on a middleware library like `tower-http` configured properly with secure defaults.
