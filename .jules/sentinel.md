## 2024-05-24 - Extracted Router for Header Safety
**Vulnerability:** API routes were being created inline in main, making it difficult to inject comprehensive security headers cleanly without causing lifetime and testing issues. The server didn't enforce critical headers like CSP or HSTS, leading to lack of defense-in-depth against XSS or clickjacking.
**Learning:** In axum, when applying multiple complex `tower_http::set_header::SetResponseHeaderLayer` overrides, you cannot easily chain `.overriding()` due to generic type mismatches; you must use multiple distinct `.layer()` calls on the axum router. Additionally, using `hyper::header` requires specific explicit constants or `HeaderName::from_static` since `http` isn't a direct dependency in this environment.
**Prevention:** Always encapsulate routing and middleware application in a distinct public function (`pub fn app(state: Arc<AppState>) -> Router`) separate from `main()`. This allows straightforward layering of security headers using independent `.layer()` chains while retaining testability.
