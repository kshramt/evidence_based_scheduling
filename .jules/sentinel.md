## 2023-10-27 - Centralized Security Headers in Axum
**Vulnerability:** Missing strict security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) in the Axum API router.
**Learning:** Axum's `tower_http::set_header::SetResponseHeaderLayer` acts as a layer constructor using `.overriding()` rather than a chainable builder. Applying multiple headers requires applying the layer multiple times to the router. Additionally, using `hyper::header` for header names and values ensures compatibility with Axum's underlying ecosystem, whereas using the generic `http` crate directly may cause compilation issues if not linked correctly. A `default-src 'none'` CSP is appropriate for a pure JSON API backend, though it would break any HTML endpoints added later.
**Prevention:** Future API additions must ensure that strict security headers are applied globally via `tower_http` middleware. Any new HTML-serving routes must be evaluated against the strict CSP to avoid breaking functionality while maintaining security.
