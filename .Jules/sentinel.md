## 2024-08-01 - Add strict security headers to Axum API
**Vulnerability:** The backend API was missing standard HTTP security headers, leaving it potentially vulnerable to basic attacks like clickjacking or MIME-type sniffing if responses were accidentally rendered by a browser.
**Learning:** Axum's `tower_http::set_header::SetResponseHeaderLayer` can be used to add headers. In `tower_http` 0.6, `SetResponseHeaderLayer::overriding()` acts as a constructor, so multiple headers require chaining multiple `.layer(...)` calls. Not all headers have named constants in `hyper::header` (e.g., `referrer-policy`), so `HeaderName::from_static()` is required. Additionally, the strict CSP (`default-src 'none'`) is safe because this specific Axum API only serves JSON (not HTML).
**Prevention:** Always ensure standard security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) are configured on all backend services, even JSON APIs, as a defense-in-depth measure.
